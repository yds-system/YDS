# Directory

디렉토리 구조

> **구상 단계** — 아직 확정되지 않은 배포 경로·파일 구조입니다. 실제 운영 전에 변경될 수 있습니다.

---

## 개요

YDS(윤컴 디자인 시스템)는 회사 공통(글로벌) 디자인 시스템으로, 모든 프로젝트가 함께 사용하는 토큰·컴포넌트·리소스를 한 곳(`/humanframe/yds/`)에서 관리한다. 각 프로젝트는 기존 경로(`/humanframe/{프로젝트명}/assets/`)를 그대로 유지하고 YDS 파일을 불러오기만 한다.

---

## 디렉토리 트리

```
/humanframe/
├─ yds/                              ← 글로벌 디자인 시스템 (모든 프로젝트 공통)
│  └─ assets/
│     ├─ css/
│     │  ├─ yds-tokens.css           ← 토큰(변수)
│     │  ├─ yds-components.css       ← 컴포넌트 (yds- 클래스)
│     │  └─ yds-base.css             ← 리셋·전역 스타일 (선택)
│     ├─ js/
│     ├─ fonts/
│     └─ images/
│        └─ icons/
└─ {프로젝트명}/assets/               ← 각 프로젝트 (기존 파일 유지)
```

---

## 불러오는 순서 (`<head>`)

기존 프로젝트 CSS가 있는 경우, YDS 파일을 그 뒤에 추가한다. 토큰이 먼저 로드되어야 컴포넌트 CSS가 올바르게 적용된다.

```html
<!-- 기존 프로젝트 CSS -->
<link rel="stylesheet" href="/humanframe/{프로젝트명}/assets/css/style.css">

<!-- YDS 토큰 (변수 정의) -->
<link rel="stylesheet" href="/humanframe/yds/assets/css/yds-tokens.css">

<!-- YDS 컴포넌트 -->
<link rel="stylesheet" href="/humanframe/yds/assets/css/yds-components.css">

<!-- yds-base.css는 기존 CSS가 없는 신규 프로젝트에만 추가 -->
```

## 운영 규칙

- **단일 경로 운영**: 버전 폴더 없이 `/humanframe/yds/` 하나로 운영한다. 파일을 수정하면 YDS를 사용하는 모든 프로젝트에 즉시 반영된다.
- **하위 호환 삭제 규칙**: 클래스명·토큰 이름은 바로 삭제하지 않는다. 새 이름을 먼저 추가하고 옛 이름에 "삭제 예정" 주석을 붙인 뒤, 모든 프로젝트에서 교체가 완료된 것을 확인하고 제거한다.
- **배포 전 필수 검증**: Storybook 화면 확인, `check:tokens`, `check:contrast` 세 가지를 모두 통과해야 배포한다.
- **yds-base.css 제외**: 기존 CSS가 있는 프로젝트는 `yds-base.css`를 추가하지 않는다. 리셋이 중복되면 기존 스타일이 깨질 수 있다.
- **프로젝트 커스터마이즈**: 프로젝트별로 바꾸고 싶은 스타일은 `/humanframe/yds/`를 직접 수정하지 않고, 해당 프로젝트의 CSS에서 덮어쓰기(override)로 처리한다.

## 불러오는 순서 (어드민 기준)

토큰 → YDS 컴포넌트 → 프로젝트 테마 → 프로젝트 컴포넌트 → 페이지 스타일 순으로 로드한다.

```html
<!-- 1. YDS 토큰 (변수 정의 — 반드시 가장 먼저) -->
<link rel="stylesheet" href="/humanframe/yds/assets/css/yds-tokens.css">

<!-- 2. YDS 컴포넌트 (yds- 클래스) -->
<link rel="stylesheet" href="/humanframe/yds/assets/css/yds-components.css">

<!-- 3. 프로젝트 테마 (YDS 시멘틱·모드 토큰 덮어쓰기) -->
<link rel="stylesheet" href="/humanframe/admin/assets/css/admin-theme.css">

<!-- 4. 프로젝트 전용 컴포넌트 (adm- 클래스) -->
<link rel="stylesheet" href="/humanframe/admin/assets/css/admin-components.css">

<!-- 5. 페이지별 스타일 -->
<link rel="stylesheet" href="/humanframe/admin/assets/css/admin.css">
```

## 프로젝트 커스터마이즈 규칙

- **시멘틱·모드 토큰만 덮어쓰기** — `[data-theme]`에서 `mode.scss`의 색상 토큰(`--color-bg-primary` 등)을 교체한다. 프리미티브(`--color-primary-50` 등)와 반응형(`--font-size-*`, `--space-*`) 수정 금지.
- **YDS 파일 직접 수정 금지** — 바꾸려면 프로젝트 `_theme.scss`의 토큰 덮어쓰기 또는 프로젝트 전용 컴포넌트로 처리한다.
- **프로젝트 컴포넌트 클래스는 프로젝트 접두사 사용** — `adm-`, `prj-` 등 프로젝트별 접두사를 붙인다. `yds-` 클래스 추가·수정 금지.
- **두 개 이상 프로젝트에서 쓰는 컴포넌트는 YDS로 이동 검토** — 반복 구현을 막기 위해 공통화를 협의한다.
- **토큰 이름 규칙**
  - *YDS 토큰 값 덮어쓰기*: 이름을 바꾸지 않고 그대로 사용한다 (예: `--color-bg-primary`). 이름이 달라지면 YDS 컴포넌트가 새 값을 참조하지 못한다.
  - *프로젝트 전용 새 토큰*: 프로젝트 접두사 필수 (예: `--adm-color-bg-banner`). `--color-*` 형식의 이름은 YDS 예약어이므로 사용 금지.
- **테마는 라이트·다크를 한 쌍으로 덮어쓴다** — `[data-theme]`(라이트)와 `[data-theme][data-mode="dark"]`(다크)를 항상 함께 작성한다. 라이트만 덮어쓰면 다크 모드에서 YDS 기본값이 그대로 노출된다. `_theme.scss` 예시 참고.
- **`/humanframe/yds/` 수정은 전 프로젝트 즉시 반영** — 단일 경로 운영이므로 파일을 수정하면 모든 프로젝트에 바로 적용된다. 배포 전 Storybook 화면 확인, `check:tokens`, `check:contrast` 필수.
- **납품 프로젝트는 YDS 동봉** — 발주처 서버에 납품하는 프로젝트는 납품 시점의 `/humanframe/yds/` 를 복사해서 함께 납품한다. 단일 경로 운영 원칙의 예외로, 납품 이후 YDS 업데이트는 별도 계약으로 처리한다.

## `_theme.scss` 예시

`src/docs/examples/_theme.example.scss` 기준. `[data-theme="project-a"]`를 `[data-theme="프로젝트명"]`으로 바꿔 사용한다.

```scss
/* _theme.scss 예시 — 프로젝트 A
   덮어쓸 수 있는 토큰 : mode.scss :root 에 정의된 시멘틱 색상 토큰
   덮어쓰기 금지       : primitive(--color-primary-50 등), responsive(--font-size-*, --space-*)
   사용 방법           : <html data-theme="project-a">
   주의                : 라이트·다크를 반드시 한 쌍으로 작성한다 */

/* ── 라이트 모드 ── */
[data-theme="project-a"] {

  /* ── 텍스트 */
  --color-text-primary:       #267337;  /* 기본값: var(--color-primary-60) */
  --color-text-link:          #228738;  /* 기본값: var(--color-primary-50) */

  /* ── 배경 */
  --color-bg-primary:          #228738;  /* 주요 버튼·CTA */
  --color-bg-primary-hover:    #267337;
  --color-bg-primary-pressed:  #285d33;
  --color-bg-primary-subtle:   #eaf6ec;  /* 연한 강조 배경 */
  --color-bg-selected:         #eaf6ec;  /* 선택 상태 행 */

  /* ── 테두리 */
  --color-border-primary:  #228738;
  --color-border-focus:    #228738;  /* 포커스 링 */

  /* ── 아이콘 */
  --color-icon-primary:    #228738;

  /* ── 필요 시 추가 가능 (주석 해제 후 사용) */
  /* --color-text-secondary:   ...;  */
  /* --color-bg-secondary:     ...;  */
  /* --color-border-secondary: ...;  */

}

/* ── 다크 모드 (라이트와 반드시 한 쌍으로 작성) ── */
[data-theme="project-a"][data-mode="dark"] {

  /* 다크 배경 위에서도 대비(WCAG AA 4.5:1)를 유지할 수 있도록
     라이트보다 밝은(채도 높은) 색을 사용한다 */

  /* ── 텍스트 */
  --color-text-primary:       #57c56e;
  --color-text-link:          #4bbf65;

  /* ── 배경 */
  --color-bg-primary:          #3aa855;
  --color-bg-primary-hover:    #3daf5a;
  --color-bg-primary-pressed:  #31904a;
  --color-bg-primary-subtle:   #0f2b14;
  --color-bg-selected:         #0f2b14;

  /* ── 테두리 */
  --color-border-primary:  #3aa855;
  --color-border-focus:    #3aa855;

  /* ── 아이콘 */
  --color-icon-primary:    #3aa855;

}
```

## 프로젝트 디자인시스템 (원본 관리)

> **구상 단계** — 아직 확정되지 않은 구조입니다. 실제 운영 전에 변경될 수 있습니다.

프로젝트 테마와 프로젝트 전용 컴포넌트를 YDS 저장소 안에서 함께 관리하는 방식입니다.

### 저장소 구조

```
YDS 저장소/
├─ src/                              ← 글로벌 YDS
├─ projects/
│  └─ {프로젝트명}/
│     ├─ tokens/
│     │  └─ _theme.scss              ← YDS 모드 토큰 덮어쓰기
│     ├─ components/
│     │  └─ {컴포넌트명}/
│     │     ├─ {컴포넌트명}.scss
│     │     ├─ {컴포넌트명}.stories.js
│     │     └─ {컴포넌트명}.mdx
│     └─ docs/
└─ dist/
   ├─ yds/assets/...                 → /humanframe/yds/
   └─ {프로젝트명}/assets/css/        → /humanframe/{프로젝트명}/
```

### 같은 저장소에서 관리하는 이유

- **검사·빌드 도구 공유** — `check:tokens`, `check:contrast`, 번들 스크립트를 YDS와 프로젝트가 함께 사용한다.
- **YDS 승격 시 폴더 이동만** — 두 개 이상 프로젝트에서 쓰는 컴포넌트는 `projects/{프로젝트명}/` → `src/`로 이동하면 끝난다.
- **한 Storybook에서 확인** — YDS 컴포넌트와 프로젝트 컴포넌트를 한 화면에서 나란히 비교할 수 있다.

### Storybook 계획

- 사이드바에 `Projects/{프로젝트명}` 섹션을 추가해 프로젝트 전용 컴포넌트를 표시한다.
- 툴바에서 테마를 전환할 수 있다 (YDS 기본 / 프로젝트).

### YDS 승격 기준

두 개 이상의 프로젝트에서 같은 컴포넌트를 사용하면 YDS로 이동을 검토한다.

## 진행 예정

1. **`--krds-*` 의존 제거** — 현재 컴포넌트 CSS가 참조하는 `--krds-*` 변수를 YDS 토큰(`--space-*`, `--radius-*` 등)으로 교체한다. 대상 목록은 `docs/krds-dependencies.md` 참고.
2. **배포 파일 생성** — `npm run build:dist` 스크립트를 추가하고 `yds-tokens.css`, `yds-components.css`를 번들링한다.
